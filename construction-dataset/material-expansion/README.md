# Дополнительные материалы: DMS, исследовательская выборка
Цель: добавить размеченные примеры слабых материалов. Это сбор данных, не обучение и не подтверждение точности 90%.

Источник: Paul Upchurch, Ransen Niu, *A Dense Material Segmentation Dataset for Indoor and Outdoor Scene Parsing*, ECCV 2022.
https://github.com/apple-aiml-research/ml-dms-dataset
Официальная разметка: https://docs-assets.developer.apple.com/ml-research/datasets/dms/dms_v1_labels.zip
SHA256: 78e22ffa002e168c096a007ad3e50aa4fb5f1d2a04182c31f1a73733d1867290

## Выборка
В архиве 44 557 записей. Источник автоматически пометил как indoor 36 598 кандидатов с ≥2% площади хотя бы одного из 21 целевого материала.
Детерминированно выбраны 8 486 уникальных кандидатов: до 600 train, 100 validation, 100 test на материал. Редкие классы могут не достигать квоты. Совместное присутствие классов увеличивает их итоговые счётчики.
Это не количество успешно скачанных фотографий: фактическое число указано в collection-report.json после окончания.
Выборка содержит краску/штукатурку/эмаль, кирпич, плитку, древесину, металл, обои, виды камня, стекло, потолочную плитку, пробку и другие материалы.
Не объединяем «полированный камень» с мрамором, «краска/штукатурка/эмаль» с чистой штукатуркой. Отдельных классов линолеума, ламината, гипсокартона и панелей здесь нет.

## Проверки
Проверяются декодирование, размеры, соответствие ориентационного дескриптора исходной разметке, диапазон ID маски. Фото сохраняются в размере исходной маски; изменения фиксируются.
Исключаются исходные Flickr-фото, уже находящиеся в нашем наборе, и близкие визуальные хеши ко всем прежним фотографиям.
Официальные DMS train/validation/test не перемешиваются. Между разделами блокируются совпадения изображения, Open Images ID и близкие визуальные хеши.
Идентификаторов зданий нет. Автоматическая фильтрация не заменяет ручную проверку и не доказывает независимость зданий.

## Как использовать
Скачайте все materials-dms-*.tar.gz из релиза materials-dms-<run_id> и распакуйте в один каталог. Скачайте manifest.jsonl, taxonomy.json, ATTRIBUTION.md, collection-report.json, collection-audit.json и SHA256SUMS.
В обучение допускаются только записи training_eligible=true; в проверку — evaluation_eligible=true с соответствующим split.
Архивы могут содержать пары, заблокированные при итоговой проверке пересечений: наличие файла само по себе не разрешает включать его в train.
ID исходной DMS-таксономии нельзя напрямую трактовать как ID существующей модели.
Шарды публикуются в черновик релиза во время сбора. Релиз становится обычным только после итогового аудита и загрузки реестра.
Это отдельный исследовательский набор. Автоматическое обучение на нём не запускается.

## Лицензии и авторство
**Разметка DMS — CC-BY-NC-4.0, только некоммерческое использование.**
Фотографии отбираются с указанной в метаданных Open Images лицензией CC-BY-2.0 и автором; автор, оригинальная страница и изменения сохраняются по каждой фотографии.
Текущие лицензии исходных страниц индивидуально не перепроверены. Лицензия кода Apple не является лицензией датасета.
Не считать эту выборку очищенной для коммерческого обучения.

## Критерий качества
90%+ — цель, а не результат сбора. Для сегментации оцениваем IoU каждого согласованного класса на независимых объектах, включая неизвестные материалы и фон.
Нельзя обещать 90% для «всех материалов», если класс отсутствует, объединён с другими или не представлен в независимой проверке.
Следующий этап: ручной аудит масок и редких классов, согласование таксономии, независимый тест и обучение подходящей модели. Текущая схема с замороженными признаками и 1×1 слоями не обеспечивает требуемое качество материалов.
